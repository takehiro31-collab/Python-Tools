# 法人向け AI業務効率化コース 5回カリキュラム表(講師用)

> 対象:事務作業が多い中小企業 / 実施形式:対面・全5回・1回2.5時間 / 使用ツール:Claude Code
> 本資料は講師の進行用です。業種・企業ごとに【差し替え】と記した箇所を書き換えて使います。

---

## 0. コース概要(1枚で確認)

| 項目 | 内容 |
|---|---|
| コース名(例) | 現場で使える AI業務自動化 実践コース(全5回) |
| 価格 | 1コース 20万円(税別)/ 初回モニター企業は 10〜15万円 |
| 回数・時間 | 全5回 × 2.5時間(合計12.5時間)、対面 |
| 推奨間隔 | 1〜2週間に1回(運用を試す期間を確保するため、第3回〜第4回の間は2週間を推奨) |
| 全体期間の目安 | 約1.5〜2.5か月 |
| 定員の目安 | 1〜4名(事務担当者)+ 第1回・第5回は決裁者(社長・部長)同席を推奨 |
| 講師の稼働 | 実施日:週1日 / 準備:平日夜・休日に週3時間程度 |
| 事前ヒアリング | 第1回の前に30〜60分(オンライン可)。成功基準・対象業務の当たりを付ける |

### 0-1. コースの目的
1. 社内の定型事務作業のうち、AIで効率化できる業務を見極めて自動化する。
2. ITに詳しくない担当者でも、自動化の仕組みを **自分で使い・直し・引き継げる** 状態にする。
3. 削減時間を数値で確認し、次に自動化する業務の計画まで持ち帰る。

### 0-2. 対象者
- 主対象:請求書処理・議事録作成・データ集計・定型メール・報告書作成などを日常的に行う事務担当者
- 前提スキル:Excel・Wordの基本操作ができる程度でよい(プログラミング経験は不要)
- 同席推奨:決裁者(第1回の成功基準合意、第5回の成果報告)

### 0-3. ゴール(成果物と数値目標の例)

| 区分 | 内容 |
|---|---|
| 成果物① | 業務棚卸しシート(業務名・頻度・所要時間・自動化優先度) |
| 成果物② | 自動化ツール 2件以上(例:Excel/CSV集計スクリプト、議事録・報告書の下書き作成手順) |
| 成果物③ | 各ツールの使い方手順書(受講者が自分の言葉で書いたもの) |
| 成果物④ | 運用ルール表(担当・頻度・保存場所・確認者・困ったときの連絡先) |
| 成果物⑤ | 効果測定レポート(導入前後の作業時間比較) |
| 成果物⑥ | 次の自動化候補ロードマップ(3〜6か月分) |
| 数値目標(例) | 対象業務で **月10時間以上の作業時間削減**(事前ヒアリングで企業ごとに決定) |
| 数値目標(例) | 対象業務の作業時間を **50%以上短縮**、または手作業による転記ミス **ゼロ** |
| 定性目標(例) | 受講者が講師なしで自動化ツールを実行・軽微な修正を指示できる |

> 数値目標は「現状の所要時間 × 月の回数」を第1回で実測・概算して決めます。根拠のない目標は設定しないこと。

### 0-4. 受講者側の事前準備(第1回の1週間前までに依頼)

| 項目 | 内容 | 確認方法 |
|---|---|---|
| PC | 受講者1人1台。Windows / Mac いずれか。社内でソフトのインストールが許可されていること | 事前チェックリストで回答 |
| 社内ルール確認 | 情報システム担当・管理者に、AIツール利用とインストールの許可を取ってもらう | 書面またはメールで許可済みと確認 |
| インターネット | 会場で安定して接続できること(社内プロキシ等の制限がある場合は事前に共有) | 事前に会場の回線を確認 |
| Claudeのアカウント/プラン | **クライアント企業名義** で、Claude Code が利用できるプランを契約(有料プランまたはAPI利用。対応プラン・料金は契約時点の公式情報で確認) | 第1回までにログイン確認 |
| Claude Code のインストール | 公式手順に沿って導入。不安な場合は講師が第1回の冒頭で一緒に行う(時間を確保済み) | 事前に講師がリモートで確認するのが理想 |
| サンプルデータ | 自動化したい業務のファイルを2〜3種類(**個人情報を含まないもの、またはダミー化したもの**) | 第1回までに講師へ共有 or 当日持参 |
| 業務メモ | 「毎週・毎月やっている面倒な作業」を5つ程度メモしておく | 第1回の棚卸しワークで使用 |

> アカウントをクライアント名義にする理由:成果物・利用データの所有を明確にし、コース終了後も企業側で使い続けられるようにするため。講師個人のアカウントで代行しない。

## 2. 各回の詳細

### 第1回 現状整理 ―「どの業務を、どれだけ減らすか」を決める

**ゴール**
- 自動化の対象業務を2件(+予備1件)に絞り込む
- 成功基準(例:月10時間削減)を決裁者と合意する
- 全員の PC で Claude Code が起動し、簡単な指示を1回成功させる

**タイムテーブル(150分)**

| 時間 | 分 | 内容 | 進行のポイント |
|---|---|---|---|
| 0:00–0:10 | 10 | オープニング:自己紹介、コースの全体像、5回のゴール説明 | 「プログラミング研修ではない」と最初に伝え、不安を下げる |
| 0:10–0:25 | 15 | デモ:AIでできること/できないこと | 事前に預かったサンプルで、集計や文書下書きを実演。「AIは間違えることがある」も必ず伝える |
| 0:25–0:55 | 30 | ワーク①:業務棚卸し | 業務棚卸しシートに、業務名・頻度・1回の所要時間・担当者・使うファイルを書き出す |
| 0:55–1:05 | 10 | 休憩 | 講師はこの間にシートを見て候補に印をつける |
| 1:05–1:30 | 25 | ワーク②:自動化候補の優先順位付け | 「頻度 × 所要時間 × 手順の決まり具合 × リスク(個人情報・金額ミスの影響)」で採点。個人情報を含む業務は今回は対象外と明示 |
| 1:30–1:50 | 20 | 成功基準の合意 | 対象業務の現状時間を概算し、目標値を決める。決裁者同席で合意し、合意書に記入 |
| 1:50–2:15 | 25 | 環境確認・初回体験 | Claude Code を起動し、「この文章を丁寧な取引先向けメールに直して」などの簡単な依頼を全員で1回成功させる |
| 2:15–2:30 | 15 | まとめ・宿題説明・次回予告 | 次回使うデータの準備を具体的に依頼(ファイル名・件数まで) |

**実施内容**
- 業務の棚卸しと、自動化の向き・不向きの判断基準の共有
  - 向いている:手順が毎回同じ/ファイル形式が決まっている/量が多い
  - 向いていない(今回は扱わない):個人情報を多く含む/判断の基準が人によって違う/1回きりの作業
- 成功基準(KPI)と測定方法の合意
- 環境の動作確認

**受講者の宿題**
1. 対象業務①・②を通常どおり1回行い、**実際にかかった時間を記録**する(効果測定の基準値になる)
2. 第2回で使うデータ(個人情報なし/ダミー化済み)を3〜5ファイル用意する
3. 対象業務の手順を、箇条書きで5〜10行に書き出す(「どこから何を開いて、何をして、どこに保存するか」)

**講師の事前準備(目安:3時間)**
- 事前ヒアリング内容から業種別の「よくある自動化候補リスト」を用意【差し替え】
- 業務棚卸しシート・成功基準合意書の印刷(人数分+予備)
- デモ用ダミーデータの作成と、デモ手順のリハーサル
- 会場のネット環境・電源・プロジェクター確認
- インストール手順の最新版を公式情報で再確認

**成果物**
- 業務棚卸しシート(記入済み)
- 成功基準合意書(対象業務・現状時間・目標値・測定方法・決裁者署名)

### 第2回 自動化1(データ集計系)― 1つ目の仕組みを動かす

**ゴール**
- 対象業務①(例:月次の売上・経費集計)を Claude Code に指示して自動化し、手作業と同じ結果が出ることを確認する
- 「良い指示の出し方」の型を身につける

**タイムテーブル(150分)**

| 時間 | 分 | 内容 | 進行のポイント |
|---|---|---|---|
| 0:00–0:10 | 10 | 振り返り・宿題確認 | 記録した作業時間を棚卸しシートに転記 |
| 0:10–0:30 | 20 | 講義:指示の出し方の基本 | 「目的・入力ファイル・欲しい結果・注意点」の4点セットで伝える型を練習。良い例/悪い例を比較 |
| 0:30–1:00 | 30 | ハンズオン①:練習用データで集計 | 講師が用意したダミーCSV/Excelを使い、「Claude Code に指示して集計用のスクリプトを作り、実行する」流れを全員で体験 |
| 1:00–1:10 | 10 | 休憩 | — |
| 1:10–1:50 | 40 | ハンズオン②:実業務データで自動化1を作る | 受講者が持参したデータで実施。講師は指示文を代わりに書かず、ヒントを出す |
| 1:50–2:10 | 20 | 検証:手作業の結果と突き合わせ | 合計値・件数・特定行を手作業結果と比較。ズレがあれば原因をAIに確認させて修正 |
| 2:10–2:20 | 10 | 手順書v1の作成 | 「どのフォルダにファイルを置き、何と指示し、結果をどこで確認するか」を受講者自身が書く |
| 2:20–2:30 | 10 | まとめ・宿題 | 次回の文書系業務のサンプル準備を依頼 |

**実施内容**
- 指示の型(目的/入力/出力/注意点)の練習
- 作業用フォルダの決め方(元データを直接書き換えない、コピーで作業する)
- 集計スクリプトの作成・実行・検証
- 「結果は必ず人が確認する」ルールの徹底

**受講者の宿題**
1. 自動化1を **実業務で2回以上** 使い、かかった時間を記録する
2. 使っていて困ったこと・エラーをメモする(画面のスクリーンショットでもよい)
3. 第3回で使う文書系サンプル(過去の議事録メモ、報告書、定型メールの例など)を2〜3件用意する

**講師の事前準備(目安:3時間)**
- 受講者から預かったデータで、事前に自動化1を一度試作しておく(当日の詰まりどころを把握)
- 練習用ダミーCSV/Excel(業種に合わせた列名)【差し替え】
- 指示文の例カード(印刷して配布)
- 検証チェック表(合計値・件数・抜き取り確認の欄)

**成果物**
- 自動化1(集計スクリプトと作業フォルダ一式)
- 手順書v1
- 検証結果の記録

### 第3回 自動化2(文書作成系)― 下書きをAIに任せ、人が仕上げる

**ゴール**
- 対象業務②(例:議事録の整形・報告書の下書き・定型メールの作成)の型を作る
- AIが作った文書を確認するチェックリストを作る

**タイムテーブル(150分)**

| 時間 | 分 | 内容 | 進行のポイント |
|---|---|---|---|
| 0:00–0:15 | 15 | 振り返り:自動化1の使用状況・困りごと | 宿題メモをもとに、その場で直せるものは直す。時間がかかるものは第4回へ回す |
| 0:15–0:35 | 20 | 講義:文書作成のテンプレート化 | 「毎回変わる部分」と「毎回同じ部分」を分ける考え方。社内の書式・言い回しを指示に含める |
| 0:35–1:05 | 30 | ハンズオン①:議事録の整形・要約 | 箇条書きメモから、社内書式の議事録(決定事項・宿題・期限)を作る |
| 1:05–1:15 | 10 | 休憩 | — |
| 1:15–1:55 | 40 | ハンズオン②:自動化2を作る | 対象業務②で、指示文テンプレートと出力のひな形を作り、ファイルとして保存して繰り返し使えるようにする |
| 1:55–2:15 | 20 | AI出力の確認ルール作り | 数字・固有名詞・日付・宛先・敬語を必ず確認する、などのチェックリストを受講者と一緒に作る |
| 2:15–2:30 | 15 | まとめ・宿題 | 次回までの2週間の運用方法を具体的に決める |

**実施内容**
- 文書系業務の「型」作り(指示文テンプレート+出力ひな形)
- AI出力の確認チェックリスト作成
- 社外に出す文書は必ず人が最終確認する、という運用ルールの合意

**受講者の宿題(第4回まで2週間を推奨)**
1. 自動化1・2を実業務で使い、**運用記録表**(日付・作業・所要時間・困ったこと)に記入する
2. 「もっとこうなれば楽」という改善要望を3つ書き出す
3. 手順書を自分で読み返し、分かりにくい箇所に印をつける

**講師の事前準備(目安:3時間)**
- 文書系サンプルを使った自動化2の試作
- 業種別の文書テンプレート例(議事録・日報・報告書・定型メール)【差し替え】
- 確認チェックリストのひな形
- 運用記録表の印刷 or 共有ファイル作成

**成果物**
- 自動化2(指示文テンプレート・出力ひな形)
- AI出力確認チェックリスト
- 手順書(自動化2分)

### 第4回 運用と改善 ― 自分たちで直せるようにする

**ゴール**
- 2週間の運用で出た課題を、受講者自身の指示で改善できる
- エラーが出たときの基本対応を身につける
- 中間の効果測定で、成功基準に対する進み具合を確認する

**タイムテーブル(150分)**

| 時間 | 分 | 内容 | 進行のポイント |
|---|---|---|---|
| 0:00–0:15 | 15 | 運用記録の確認 | 運用記録表を全員で見て、課題を「すぐ直す/運用で回避/範囲外」に分類 |
| 0:15–0:45 | 30 | ハンズオン①:エラー対応の練習 | 列名が変わった・空欄がある・ファイル名が違うなど、わざと崩したデータで練習。「エラー内容をそのままAIに伝えて原因を聞く」型を習得 |
| 0:45–1:15 | 30 | ハンズオン②:改善 | 宿題の改善要望をもとに、受講者が自分で修正を指示。講師は見守りとヒントのみ |
| 1:15–1:25 | 10 | 休憩 | — |
| 1:25–1:55 | 30 | 効果測定(中間) | 導入前の時間と現在の時間を比較し、月あたりの削減時間を計算。目標との差を確認 |
| 1:55–2:20 | 25 | 運用ルール作り | 誰が・いつ・どのファイルで・どこに保存・誰が確認・困ったら誰に連絡、を表にまとめる |
| 2:20–2:30 | 10 | まとめ・宿題 | 第5回の実演と成果報告の準備を依頼。決裁者の同席を再依頼 |

**実施内容**
- エラー対応の基本(落ち着いて、エラー文をコピーしてAIに相談、元データは触らない)
- 受講者主導の改善
- 中間効果測定と、目標未達の場合の打ち手検討
- 運用ルール表の作成

**受講者の宿題**
1. 改善版ツールで運用を継続し、運用記録をつける
2. 第5回で行う「講師なし実演」の練習を1回行う
3. 次に自動化したい業務を2〜3件、棚卸しシートに追記する

**講師の事前準備(目安:3時間)**
- 運用記録表を事前に受け取り(可能なら)、課題を整理
- エラー練習用の「崩したデータ」の作成
- 効果測定シート(計算式入り)の準備
- 運用ルール表のひな形
- 範囲外の要望が出た場合の別見積もり条件の整理

**成果物**
- 改善版の自動化1・2
- 運用ルール表
- 効果測定(中間)

### 第5回 定着(引き継ぎ)― 講師なしで回る状態を確認する

**ゴール**
- 受講者が講師の手助けなしで自動化ツールを実行できることを確認する
- 決裁者に成果を報告し、次の自動化計画を合意する
- コース後のサポート(保守・顧問契約)を案内する

**タイムテーブル(150分)**

| 時間 | 分 | 内容 | 進行のポイント |
|---|---|---|---|
| 0:00–0:15 | 15 | 振り返り:5回で作ったもの・できるようになったこと | 第1回の棚卸しシートと比べて変化を見える化 |
| 0:15–0:45 | 30 | 受講者による実演 | 講師は口を出さない。詰まった箇所は「引き継ぎ資料に追記すべき点」として記録 |
| 0:45–1:10 | 25 | 引き継ぎ資料の完成 | 手順書・運用ルール・確認チェックリスト・トラブル対応メモを1冊にまとめる |
| 1:10–1:20 | 10 | 休憩 | 決裁者が合流するタイミングとして使う |
| 1:20–1:45 | 25 | 成果報告(決裁者同席) | 受講者が発表。削減時間・ミスの減少・担当者の声を数値と事例で示す |
| 1:45–2:05 | 20 | 次の自動化ロードマップ | 追加候補を優先順位付けし、3〜6か月の計画にする。「自社でできるもの」と「支援があると早いもの」に分ける |

- 効果測定の最終報告
- ロードマップ作成とサポートの案内

**受講者の宿題(コース後)**
- 引き継ぎ資料に沿って運用を継続し、1か月後に削減時間を再測定する(フォローアップ面談で確認)

**講師の事前準備(目安:3時間)**
- 効果測定レポートのひな形(グラフ入り)
- 引き継ぎ資料の目次・表紙
- 保守・顧問契約の提案書(料金表・サポート範囲)
- アンケート用紙
- 修了証(任意。受講者のモチベーション向上に有効)

**成果物**
- 引き継ぎ資料一式(手順書・運用ルール・チェックリスト・トラブル対応メモ)
- 効果測定レポート(最終)
- 次の自動化ロードマップ
- 保守・顧問契約の提案書

## 3. 講師が使い回せるテンプレートの考え方

準備時間を週3時間に収めるため、**共通部分は一度作って固定し、企業ごとには差し替え部分だけを直す**。

### 3-1. 共通部分(全社で同じものを使う)

| 資料 | 内容 |
|---|---|
| コース説明資料 | 目的・5回の流れ・AIでできること/できないこと・注意事項 |
| 業務棚卸しシート | 業務名・頻度・所要時間・担当・ファイル形式・個人情報の有無・優先度スコア |
| 成功基準合意書 | 対象業務・現状時間・目標値・測定方法・署名欄 |
| 指示の型カード | 目的/入力/出力/注意点の4点セットと例文 |
| 検証チェック表 | 合計値・件数・抜き取り確認 |
| AI出力確認チェックリスト | 数字・固有名詞・日付・宛先・敬語・社外秘情報 |
| 運用記録表/運用ルール表 | 日付・作業・時間・困りごと/担当・頻度・保存場所・確認者・連絡先 |
| 効果測定シート | 導入前後の時間 × 月の回数 = 月間削減時間(計算式入り) |
| エラー対応の基本手順 | 落ち着く → エラー文をコピー → AIに相談 → 直らなければ連絡 |
| アンケート・提案書の枠 | 料金表・サポート範囲の定型文 |

### 3-2. 差し替え部分(業種・企業ごとに作る)

| 差し替え項目 | 製造業の例 | 不動産業の例 | 士業事務所の例 | 小売・卸の例 |
|---|---|---|---|---|
| 自動化候補リスト | 日報集計、在庫表の更新 | 物件情報の一覧化、案内メール | 書類チェックリスト、定型案内文 | 売上日報、発注集計 |
| 練習用ダミーデータ | 製品コード・数量・ライン名 | 物件番号・賃料・エリア | 案件番号・期限・手続き種別 | 店舗名・品目・売上 |
| 文書テンプレート例 | 品質会議の議事録 | 内見後のお礼メール | 期限案内メール | 店長会議の報告書 |
| デモの題材 | 月次生産実績の集計 | 物件一覧の整形 | 期限一覧の作成 | 店舗別売上の集計 |
| 用語・言い回し | 社内の略語・部署名 | 業界用語 | 専門用語の扱い | 商品カテゴリ名 |

### 3-3. 運用のコツ
- 差し替え部分は「業種別フォルダ」に保存し、2社目以降は似た業種から複製して直す。
- 各社で作った指示文のうち、うまくいったものは(企業固有の情報を除いて)共通の「指示文ライブラリ」に追加していく。
- クライアントのデータそのものは、NDAで認められた範囲を超えて保存・流用しない。

## 4. 想定トラブルと対処

| トラブル | 予防策 | 当日の対処 |
|---|---|---|
| Claude Code が起動しない・インストールできない | 事前に環境チェックリストを回収。可能ならリモートで事前確認 | 講師PCで画面共有しながら進め、受講者はペアで操作。休憩中に個別対応。直らなければ次回までに別途対応 |
| 社内ネットワークの制限で接続できない | 事前ヒアリングで情報システム担当に確認 | モバイル回線などの代替手段(会社の許可がある場合のみ)。無理なら当日はデモ中心に切り替え |
| アカウント・プランが未準備/利用上限に達した | 1週間前にログイン確認を依頼 | 講師のデモ環境で進行(ダミーデータのみ)。次回までに準備を依頼 |
| 受講者のレベル差が大きい | 第1回で操作の得意・不得意を確認 | 早い人には「応用課題」(列の追加、別ファイルへの展開)を用意。遅い人には手順カードを渡し、講師が優先的にフォロー。ペアを組ませる |
| 自動化対象が決まらない | 事前ヒアリングで業種別候補リストを提示 | 「毎月必ずやる・30分以上かかる・手順が同じ」の3条件で絞る。それでも決まらなければ講師が候補を2つ提案して選んでもらう |
| 個人情報を含む業務しか候補がない | 契約時に「個人情報を含む業務は初期対象外」と明記 | ダミー化(氏名を記号に置換など)した上で手順だけ作る。本番適用はNDA・社内規程の確認後に別途検討 |
| AIの結果が間違っている・毎回違う | 「AIは間違えることがある」を第1回で共有 | 手作業結果と突き合わせる検証を必ず行う。指示を具体化する(列名・計算方法を明記)。数値計算はスクリプト化して結果を安定させる |
| 宿題(時間記録)をやってこない | 記録表を簡単にする(1行で書ける形式) | 当日に記憶ベースで概算し、次回から記録してもらう。効果測定ができないと成果を示せないことを丁寧に説明 |
| 範囲外の開発を求められる | 契約書で範囲を明記 | 「ロードマップに載せましょう」と受け止め、別見積もりまたは顧問契約の対象として案内する。その場で約束しない |
| 決裁者が同席できない | 第1回申込時に第1回・第5回の同席を依頼 | 成果報告を A4 1枚にまとめて後日共有。必要なら短時間の報告会を別日に設定 |
| 担当者が途中で異動・退職 | 手順書を毎回更新し、受講者を2名以上にする | 引き継ぎ資料を早めに作り、後任者向けに短時間の補講を提案(別料金の可能性を事前に明記) |
| 時間が足りない | 各回の「削ってよいパート」を事前に決めておく | 検証と手順書作成は削らない。講義パートを短縮し、資料配布で補う |

## 5. 第5回での保守・顧問契約の提案

### 5-1. 自然に提案するための流れ

売り込みではなく、**「成果報告 → 残った課題 → 次の計画 → その実現手段」** の順で話すと自然につながる。

| ステップ | タイミング | 話す内容(例) |
|---|---|---|
| ① 成果の確認 | 成果報告(1:20〜) | 「月◯時間の削減ができました。当初目標の◯%です」と数値で示す |
| ② 残った課題の共有 | 成果報告の最後 | 「実演で詰まった点」「範囲外として保留した要望」を一覧で見せる |
| ③ 次の計画 | ロードマップ(1:45〜) | 次の候補業務を並べ、「自社でできるもの」「支援があると早いもの」に分ける |
| ④ 選択肢の提示 | サポートのご案内(2:05〜) | 「このまま自社で進める」「必要なときだけスポット相談」「月額で伴走」の3択で示す。どれを選んでもよいと伝える |
| ⑤ 後日のフォロー | 1か月後 | 再測定のフォローアップ面談(コースに含める)で、運用状況を見て改めて相談 |

> 伏線:第1回から「範囲外の要望」はロードマップ候補として記録し続けておく。第4回で「今後の運用で困ったときの相談先」を話題にしておく。

### 5-2. 提案内容の例

| プラン | 月額(税別) | 内容 | 向いている企業 |
|---|---|---|---|
| ライト保守 | 3万円 | ・メール/チャットでの質問対応(月◯件まで、◯営業日以内に回答)<br>・作成済みツールの軽微な修正(データの列名変更への対応など)<br>・月1回 30分のオンライン相談 | 作ったツールを安定して使い続けたい |
| スタンダード顧問 | 5万円 | ・ライト保守の内容すべて<br>・月1回 60〜90分の訪問またはオンライン定例<br>・新しい自動化1件/月程度の小規模な追加(規模の目安を明記)<br>・四半期ごとの効果測定レポート | ロードマップに沿って自動化を広げたい |
| スポット相談 | 1回あたり◯万円 | ・必要なときだけ単発で相談・修正 | 月額契約はまだ様子を見たい |

**提案書に入れる項目**
- コースの成果まとめ(削減時間・成果物)
- 今後の課題とロードマップ
- プランの比較表と料金
- 契約期間(例:最短3か月、以降1か月ごとの自動更新)と解約条件
- 対応時間(副業のため「平日夜・休日中心、回答は◯営業日以内」と明記)
- 含まないもの(下記6章と同様)

> 副業での稼働のため、即時対応・常時対応を約束しない。対応時間と回答期限を必ず書面にする。

## 6. 契約時に明記すべき範囲

### 6-1. 研修コース(20万円)に含むもの/含まないもの

| 含むもの | 含まないもの(別見積もり・別契約) |
|---|---|
| 事前ヒアリング(30〜60分) | 6回目以降の追加研修・追加訪問 |
| 対面研修 全5回 × 2.5時間 | 合意した対象業務(2件+予備1件)以外の自動化開発 |
| 各回の資料・テンプレート(棚卸しシート、手順書ひな形等) | 個人情報を含む業務の自動化(NDA・社内規程の確認後に別途協議) |
| 対象業務2件程度の自動化支援(受講者と一緒に作成) | 基幹システム・会計ソフト等との連携開発 |
| 各回の間のメール質問対応(回数・回答期限を明記) | 講師による作業代行(受講者不在での開発) |
| 効果測定のサポートと最終レポート | Claude のアカウント・プラン料金、PC・ソフト等の費用 |
| コース終了1か月後のフォローアップ面談(30分) | コース終了後の保守・修正(保守・顧問契約の対象) |
| | 交通費(遠方の場合)、会場費 |

### 6-2. 契約書・申込書に書く項目チェックリスト

| 項目 | 記載例・ポイント |
|---|---|
| 目的と対象業務 | 第1回で確定する対象業務(2件+予備1件)。変更時は双方合意 |
| 成功基準 | 例:対象業務で月10時間削減を目標とする(**努力目標であり、成果を保証するものではない**と明記) |
| 料金と支払条件 | 20万円(モニター価格の場合はその旨と条件:事例紹介・アンケート協力など)。前払い/分割、支払期限 |
| 日程と変更・キャンセル | 日程変更は◯日前まで。直前キャンセル時の扱い |
| 秘密保持(NDA) | 受け取るデータの範囲、保存場所・期間、終了後の削除方法 |
| 個人情報の扱い | 初期は個人情報を含むデータを扱わない。扱う場合は別途合意 |
| AIツールの利用 | クライアント名義のアカウントで利用。AIツールの利用規約・データの取り扱いはクライアント側でも確認すること |
| 成果物の権利 | 作成した手順書・スクリプト等はクライアントが社内で自由に使用可。講師は企業固有情報を除いたノウハウを再利用できる |
| 免責 | AIの出力に誤りが含まれる可能性があり、最終確認はクライアントが行う。ツール利用により生じた損害の責任範囲(上限は受領金額まで、など) |
| 範囲外の依頼 | 範囲外の依頼は別見積もり。その場で口頭合意しない |
| 質問対応 | 期間中のメール質問は◯件まで、◯営業日以内に回答 |
| 実施者の体制 | 個人での実施であり、対応可能な日時に限りがあること |

> 契約書の最終版は、必要に応じて専門家(弁護士等)に確認してもらうことを推奨します。
